`MEMORY.md` — это файл долгосрочной памяти для AI‑агента (в том числе для SourceCraft и аналогов): в нём хранят факты, которые агент должен помнить между сессиями и учитывать в работе. В отличие от `SKILL.md` (правила поведения), это именно **база фактов**, а не инструкции.

---

## Что обычно пишут в `MEMORY.md`

### Факты о проекте и стеке (самое полезное для разработчика)
- Версия Laravel, Vue, TypeScript, Node, PHP — чтобы агент не предлагал устаревшие API.
- Особенности архитектуры: «монолит», «API‑first», «микросервисы из X сервисов».
- Соглашения по именованию: «контроллеры в единственном числе», «DTO с суффиксом `Request`», «компоненты в PascalCase».
- Специфичные доменные термины и сокращения: «ОР — это объект расчёта», «КД — карточка документа».

### Важные решения и ограничения
- «Не использовать Redis для этой задачи, только БД».
- «Все новые эндпоинты должны быть в `/api/v2`».
- «Для валидации использовать только Form Request, не inline в контроллере».
- «Никаких новых зависимостей без согласования в PR».

### Предпочтения и стиль
- «Предпочитаю Composition API, без Options API».
- «Типизация: избегать `any`, использовать интерфейсы».
- «Логика контроллеров должна быть минимальной, выносить в сервисы».

### Конфигурация и окружение
- «База данных: PostgreSQL 15, схема `public`».
- «Хост API в dev: `localhost:8080`, в staging: `api.staging.example.com`».
- «ID проекта в аналитике: `YM-123456`».

### Секреты и безопасность (только маскированные)
Никогда не пиши реальные ключи, но можно зафиксировать факт:
- «У нас есть API‑ключ для сервиса X, он хранится в `.env` как `X_API_KEY`».
Это помогает агенту правильно подставлять переменные окружения и не хардкодить значения.

### Примеры типичного содержимого (под твой стек Laravel + Vue 3)

```markdown
# MEMORY.md — долгосрочная память проекта

## Проект
- Название: Internal Order System
- Статус: production (ветка main)
- Стек: Laravel 11, Vue 3 + TypeScript, Pinia, Vite, PostgreSQL 15

## Архитектура
- API‑first: фронтенд полностью отделён, общается через JSON API.
- Контроллеры тонкие: вся бизнес‑логика в сервисах/use‑cases.
- Валидация строго через Form Request.

## Соглашения по коду
- Контроллеры: единственное число (OrderController, а не OrdersController).
- DTO/Request: суффикс `Request` (CreateOrderRequest, UpdateOrderRequest).
- Компоненты Vue: PascalCase (OrderList.vue, OrderForm.vue).
- Composables: папка `resources/js/composables/`.
- Pinia сторы: `resources/js/stores/`.

## Доменные термины
- ОР — объект расчёта (не путать с «заказ»).
- КД — карточка документа (UI‑термин).
- Статус «в работе» в БД хранится как `in_progress`.

## Важные ограничения
- Не добавлять новые зависимости без обсуждения в PR.
- Все новые эндпоинты — только в префиксе `/api/v2`.
- Не использовать `dd()` / `var_dump()` в коде.

## Окружения
- Dev: localhost:8080, БД: pg-dev.internal
- Staging: api.staging.example.com
- Production: api.example.com

## Интеграции
- Яндекс Метрика: счётчик VITE_YM_ID=123456 (подставляется через Vite).
- Отправка уведомлений: через сервис NotificationsService (не напрямую в RabbitMQ).
```

## Чем `MEMORY.md` отличается от `SKILL.md`

| Файл | Что это | Кто пишет | Коммитится ли в Git |
|------|---------|-----------|--------------------|
| `SKILL.md` | Правила поведения агента: scope, стиль, безопасность, запреты | Человек (ты) | Да — часть проекта |
| `MEMORY.md` | Факты о проекте, принятые решения, доменные термины | Человек + агент (может дополнять сам) | Зависит от инструмента: часто **не коммитится**, потому что это персональная память агента на машине |

> ⚠️ Важный нюанс: в некоторых инструментах (например, Claude Code) `MEMORY.md` — это внутренний файл агента, который не предназначен для Git. Если ты положишь его в репозиторий, коллеги увидят твои личные заметки, а агент может начать их «цитировать» как требования. Для общих правил используй `SKILL.md`, `RULES.md` или `CONTRIBUTING.md`.

## Практические советы под твои задачи (портфолио, ревью, воспроизводимость)

- **Для портфолио и ревью** лучше выносить архитектурные решения и соглашения в `SKILL.md` и `CONTRIBUTING.md` — они коммитятся и видны всем.
- **В `MEMORY.md`** держи то, что важно именно тебе как разработчику с агентом: текущие задачи, временные ограничения, специфические ID, нюансы, которые легко забыть.
- **Держи файл коротким** (первые 200–300 строк самые важные): многие агенты загружают в контекст только начало файла.
- **Разбивай на тематические файлы**, если становится много: `memory/architecture.md`, `memory/domain.md`, `memory/decisions.md`, а в `MEMORY.md` оставь оглавление.
