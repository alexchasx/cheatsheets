`/memory` в Claude Code — это встроенная CLI‑команда для управления **автоматической памятью** (auto memory) — механизмом, который позволяет Claude запоминать важные детали проекта между сессиями и использовать их в дальнейшей работе.

## Что делает команда `/memory`

В сессии Claude Code команда `/memory`:

- **Показывает панель управления памятью**: статус авто‑памяти (включена/выключена), какие файлы инструкций загружены (например, `CLAUDE.md`, `CLAUDE.local.md` и т. п.).
- **Даёт переключатель** для включения/отключения авто‑памяти прямо в текущей сессии.
- **Предоставляет ссылку/кнопку**, чтобы открыть на диске папку с файлами памяти проекта (обычно это `~/.claude/projects/<путь-к-проекту>/memory/`).
- Позволяет **вручную редактировать или очищать** память: файлы там обычные Markdown‑файлы, их можно править в редакторе.

---

## Как устроена память под капотом

- Главный файл — `MEMORY.md` (именно заглавными) в папке проекта. Это оглавление и краткие заметки, которые Claude сам формирует по ходу работы (на основе повторяющихся правок, паттернов, принятых решений).
- Дополнительно Claude может создавать **тематические файлы** (например, `debugging.md`, `api-conventions.md`) для более детальных заметок по темам — они подгружаются не целиком, а по мере релевантности задачи.
- При старте сессии в контекст попадает **только первые 200 строк `MEMORY.md` или первые 25 КБ** (что раньше закончится). Поэтому в `MEMORY.md` хранят именно «оглавление» и самое важное, а детали — в отдельных файлах.

---

## В чём разница между `CLAUDE.md` и `/memory` (авто‑памятью)

| Что | Кто управляет | Когда загружается | Для чего лучше |
|---|---|---|---|
| `CLAUDE.md` | Вы вручную пишете правила | Всегда в начале сессии | Долговременные, жёсткие инструкции (workflow, тесты, запреты, архитектура) |
| Авто‑память (`/memory`, `MEMORY.md`) | Claude сам записывает по ходу работы | Частично при старте + по запросу темы | Повторяющиеся паттерны, привычки, локальные «хитрости» проекта |

Правило хорошего тона: если знание критично и его нельзя потерять — пишите в `CLAUDE.md`. Если это «привычки», которые Claude может выучить из правок, — пусть живёт в авто‑памяти.

---

## Практические сценарии

- **Посмотреть, что Claude «запомнил»**: в сессии введите `/memory`, откройте папку и прочитайте `MEMORY.md`.
- **Очистить устаревшее**: либо вручную удалите лишнее в `MEMORY.md`, либо попросите Claude: «почисти MEMORY.md, убери устаревшие заметки».
- **Отключить авто‑память** (например, на чужом или чувствительном проекте): через переключатель в панели `/memory` либо в `settings.json` проекта установить `"autoMemoryEnabled": false`.

---

## Важные нюансы

- Память **machine‑local**: хранится на вашем компьютере в файлах, не синхронизируется между машинами автоматически.
- Нужна версия Claude Code **не ниже 2.1.59** (проверьте `claude --version`).
- Это не «бесконечный мозг»: есть лимиты на объём, загружаемый в начало сессии, и Claude сам решает, что считать достаточно полезным для сохранения.

Учитывая ваш прошлый интерес к инструментам для разработчиков (Vue, Laravel, PHP, профайлерам и т. д.), авто‑память в Claude Code может быть полезна, чтобы ассистент быстрее «въезжал» в ваш стек и стиль проекта — но критичные правила (например, стандарты кода, обязательные шаги деплоя) всё равно лучше фиксировать в `CLAUDE.md`.
