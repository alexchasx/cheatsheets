# можно ли в source craft code assistant применять skills.md?

**Да, в SourceCraft Code Assistant можно применять `SKILL.md`** — это штатный механизм кастомизации агента под проект [1].

## Как это работает

`SKILL.md` описывает отдельный «навык» (автоматизируемый сценарий) с чёткими границами: когда его применять, какие инструменты разрешены, какие скрипты запускать и т. д. Агент:

* **Читает описание в frontmatter** (YAML-блок вверху файла) и по полю `description` сам решает, подходит ли навык под текущую задачу (автоматическая активация).
* **Позволяет вызывать вручную** через слэш‑команду: `/имя-навыка` (поле `name` в frontmatter).
* **Загружает только нужный контекст**: пока навык не активирован, его детали не занимают место в основном контексте — это экономит токены [2].

## Пример `SKILL.md` для твоего стека (Laravel + Vue 3 + TypeScript)

Допустим, ты хочешь, чтобы агент автоматически создавал Vue‑компонент по шаблону и добавлял его в роутинг. Файл может выглядеть так:

```markdown
---
name: create-vue-component
description: Создаёт новый Vue 3 компонент с Composition API и `<script setup>`, добавляет его в соответствующий роут и регистрирует в зависимостях. Используй этот навык, когда нужно быстро добавить страницу или виджет.
allowed-tools:
  - Read
  - Write
  - Bash
  - Git
context: fork
---

### Шаги

1. Создай файл компонента в `resources/js/components/` с именем в PascalCase, например `UserProfile.vue`.
2. Используй шаблон Composition API + `<script setup>` и типизируй пропсы через TypeScript-интерфейсы (создай интерфейс в `resources/js/types/`).
3. Добавь компонент в соответствующий роут в `resources/js/router/index.ts`.
4. Если нужно, обнови зависимости в `package.json` (только если явно указано в задаче).

### Требования к коду

- Имена компонентов — PascalCase.
- Пропсы — camelCase.
- Избегай `any`; используй конкретные типы или интерфейсы.
- Не меняй глобальные конфиги (например, `vite.config.ts`) без отдельного подтверждения.

### Примеры

**Плохой пример (не делай так):**
```typescript
const props = defineProps({ user: any })
```

**Хороший пример:**
```typescript
interface UserProfileProps {
  user: UserDto
}
const props = defineProps<UserProfileProps>()
```
```

Теперь агент при задаче вроде «создай компонент профиля пользователя» может сам подхватить этот навык и выполнить всё по шагам, не спрашивая каждый раз про стиль и структуру.

## Важные нюансы

* **Где хранить.** Обычно создают папку `skills/` в корне проекта и кладут туда отдельные навыки: `skills/create-vue-component/SKILL.md`, `skills/laravel-resource/SKILL.md` и т. п.
* **Не путай с `AGENTS.md`.** `AGENTS.md` — это «общая инструкция по проекту» (архитектура, стек, запреты, команды запуска), она попадает в системный промпт и всегда видна агенту. `SKILL.md` — это отдельные сценарии, которые активируются по необходимости. Для твоего стека лучше держать оба файла: `AGENTS.md` задаёт общий контекст, а `SKILL.md` автоматизирует типовые задачи.
* **Скрипты и ресурсы.** Если навыку нужны скрипты (например, bash‑скрипт генерации), положи их в подпапку `scripts/` рядом с `SKILL.md` и укажи в файле.

## Практический совет для тебя

Учитывая, что ты работаешь с Laravel и Vue 3, имеет смысл вынести в отдельные навыки:
* создание Laravel‑ресурса (API) по стандартам проекта;
* создание Vue‑компонента с правильной типизацией;
* генерацию тестов (PHPUnit + Vitest) под новую фичу.

Это сильно ускорит рутину и снизит количество ошибок из‑за несоответствия стилю.

Если скажешь, какую именно типовую задачу ты чаще всего делаешь (например, «добавить новый API‑эндпоинт» или «создать страницу на Vue»), я помогу оформить под неё готовый `SKILL.md`.
