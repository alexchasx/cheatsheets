**Микрозадачи (microtasks)** и **макрозадачи (macrotasks)** — это два типа асинхронных задач в JavaScript, которые обрабатываются в разном порядке благодаря механизму Event Loop («цикл событий»).

---

## Что это такое простыми словами

- **Микрозадача** — это короткая, высокоприоритетная задача, которую движок старается выполнить как можно скорее: сразу после текущего синхронного кода и до любых «обычных» асинхронных операций.
- **Макрозадача** — это «обычная» асинхронная задача, которая ждёт своей очереди и выполняется по одной за каждый проход Event Loop. Между макрозадачами браузер успевает, например, перерисовать интерфейс.

---

## Примеры

### Микрозадачи
- `Promise.then()`, `.catch()`, `.finally()`
- `queueMicrotask(fn)` (явный API для микрозадач)
- `MutationObserver` (отслеживание изменений DOM)
- В Node.js ещё и `process.nextTick()` (у него особый приоритет — даже выше обычных микрозадач).

### Макрозадачи
- `setTimeout`, `setInterval`
- События DOM: `click`, `scroll`, `keydown` и т. п.
- Сетевые операции: колбэки после `fetch`, `XMLHttpRequest`
- `requestAnimationFrame`
- В Node.js: операции ввода‑вывода (I/O), таймеры и др.

---

## Как Event Loop их обрабатывает (порядок)

Алгоритм примерно такой:

1. **Выполнить весь синхронный код** (то, что сразу в стеке вызовов).
2. **Обработать всю очередь микрозадач** — все накопленные микрозадачи выполняются подряд, пока очередь не опустеет. Если во время их выполнения создаются новые микрозадачи, они тоже будут выполнены в этом же проходе.
3. **Взять одну макрозадачу** из очереди макрозадач и выполнить её.
4. **Снова проверить очередь микрозадач**: если там что‑то появилось во время выполнения макрозадачи — выполнить всё.
5. **Повторить** цикл.

Из‑за этого микрозадачи почти всегда выполняются раньше макрозадач, даже если макрозадача была поставлена в очередь раньше.

---

## Наглядный пример

```js
console.log('1');

setTimeout(() => console.log('2'), 0); // макрозадача

Promise.resolve().then(() => console.log('3')); // микрозадача

console.log('4');
```

Порядок вывода: `1`, `4`, `3`, `2`.

Объяснение: сначала синхронный код (`1`, `4`), затем все микрозадачи (`3`), затем первая макрозадача (`2`).

---

## Важные нюансы

- **Рендеринг UI происходит между макрозадачами**. Поэтому, если у тебя много микрозадач подряд, интерфейс не успеет обновиться: браузер «висит», пока не закончатся все микрозадачи.
- **Бесконечные микрозадачи могут «подвесить» страницу**. Если в микрозадаче постоянно создаются новые микрозадачи, очередь никогда не опустеет, и Event Loop не дойдёт до макрозадач (и до рендера).
- **`async/await` работает через промисы**: каждый `await` — это по сути переход к микрозадаче после завершения промиса.

---

## Связь с твоими прошлыми темами

- **Vue.js** (ты интересовался Composition API, `nextTick`): `nextTick` во Vue как раз ждёт обновления DOM, которое гарантированно происходит между макрозадачами. Поэтому Vue использует микрозадачи/очередь рендера, чтобы дать фреймворку время перерисовать шаблон перед тем, как ты будешь читать DOM.
- **Node.js и очереди задач**: если ты делаешь фоновые воркеры или обрабатываешь очереди (как в Laravel), понимание микро‑ и макрозадач помогает предсказывать порядок выполнения колбэков, таймеров и промисов.
- **Собеседования по JS и SQL/бэкенду**: вопросы про Event Loop, порядок `setTimeout` и `Promise`, а также про то, почему `process.nextTick` в Node ведёт себя «не так, как ожидается», — классика на интервью.

## Пример, близкий к реальным кейсам (Vue + микрозадачи)

```js
data() {
  return { items: [] };
},
methods: {
  addItem() {
    this.items.push('новый элемент');
    // DOM ещё не обновился: Vue откладывает перерисовку на микрозадачу
    console.log(this.$refs.list); // может быть null или без нового элемента

    this.$nextTick(() => {
      // Здесь DOM уже обновлён
      console.log(this.$refs.list);
    });
  }
}
```
