## Краткий конспект по основам TypeScript

### Что это и как работает
- **TypeScript (TS)** — надмножество JavaScript: любой JS‑код валиден в TS, но TS добавляет возможности, которых нет в JS.
- **Статическая типизация**: типы проверяются на этапе компиляции, а не во время выполнения. Это помогает ловить ошибки до запуска.
- **Компиляция в JS**: TS‑код компилируется в обычный JavaScript (через `tsc` или сборщики) и выполняется везде, где работает JS.

---

### Базовые типы
- `string`, `number`, `boolean` — простые типы.
- `any` — отключает проверку типов (использовать осторожно).
- `void` — для функций, которые ничего не возвращают.
- `null` и `undefined` — отдельные значения с собственными типами.
- Массивы: `number[]` или `Array<number>`.
- Кортежи: `[string, number]` — фиксированный набор типов в заданном порядке.
- Объединения: `string | number` — значение может быть одного из указанных типов.

---

### Аннотации типов
- Переменные: `let age: number = 25;`
- Параметры и возвращаемый тип функции:
  ```ts
  function add(a: number, b: number): number {
    return a + b;
  }
  ```
- Вывод типов: если тип очевиден, его можно не указывать — TS сам его выведет.

---

### Интерфейсы и типы объектов
- **Интерфейсы** описывают структуру объектов:
  ```ts
  interface User {
    id: number;
    name: string;
    isActive?: boolean; // необязательное поле
  }
  ```
- **Типы** можно использовать для алиасов и сложных конструкций:
  ```ts
  type Point = { x: number; y: number };
  ```

---

### Классы и ООП
- Классы в TS поддерживают модификаторы доступа: `public`, `private`, `protected`.
- Наследование: `class Admin extends User { ... }`.
- Реализация интерфейса: `class User implements UserInterface { ... }`.

---

### Дженерики (обобщения)
Позволяют писать функции и классы, работающие с разными типами:
```ts
function identity<T>(arg: T): T {
  return arg;
}
```

---

### Опциональные и readonly поля
- `?` — необязательное свойство.
- `readonly` — поле можно установить только при создании, дальше менять нельзя:
  ```ts
  interface Point {
    readonly x: number;
    readonly y: number;
  }
  ```

---

### Перечисления (enum)
```ts
enum Role {
  Admin = 'ADMIN',
  User = 'USER',
}
```
Удобно для ограниченного набора именованных значений.

---

### Основные конструкции и нюансы
- **Type assertions** (`as` или `<Type>`) — явное указание типа, когда TS не может его вывести. Использовать аккуратно.
- **Union/Intersection types**: `A | B` (или), `A & B` (и).
- **Null safety**: TS различает `null`, `undefined` и обычные значения; можно явно указывать, что поле может быть `null`.

---

### Практические моменты
- **tsconfig.json** — файл конфигурации проекта (целевая версия JS, модули, strict-режимы и т. д.).
- **Строгий режим** (`"strict": true`) рекомендуется включать: он включает проверки вроде `noImplicitAny`, `strictNullChecks` и др.
- Установка и компиляция:
  - `npm install -g typescript`
  - Компиляция файла: `tsc file.ts`

---

### Связь с тем, что вы уже изучали
- Учитывая ваш интерес к **Vue, Laravel, SOLID и DDD**, TS особенно полезен: он помогает чётко описывать сущности домена (интерфейсы/типы), контракты компонентов и API, а также поддерживать модульную структуру кода.
- Для **фронтенда (Vue + Composition API)** TS даёт автодополнение и проверку пропсов, реактивных переменных и типов событий.
- В **бэкенде (Laravel-подобные архитектуры)** TS (например, на Node.js + NestJS) помогает типизировать DTO, валидацию запросов и контракты сервисов — это хорошо ложится на принципы SOLID и DDD.
