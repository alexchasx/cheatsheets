API (Application Programming Interface — «программный интерфейс приложения).
Способ общения программ друг с дуругом.

## REST
Representational State Transfer - передача состояния представления. 
Предоставление данных в качестве ресурсов.

- Клиент-серверная архитектура
- Нет состояния
- Кешируется
- Могут быть посредники между клиентом и сервером

В REST все делается с помощью HTTP-методов, таких как GET, POST, PUT, DELETE, OPTIONS, PATCH.

## GraphQL 
Это протокол для запроса связанных данных. Удобен для фронта и мобильных клиентов. 
Сложен в кэшировании.
Имееет 3 типа запросов:
- query (запрос данных. Аналогичен GET-запросу в REST API)
- mutation (изменение данных)
- subscribtion (получение данных постепенно через веб-сокет (стриминг))

## RPC 
Remote Procedure Call - удалённый вызов процедур.
Вызываем удалённо функцию с набором аргументов и получаем её результат обратно.

RPC использует GET для получения информации и POST для всего остального.

## SOAP 
Simple Object Access Protocol — простой протокол доступа к объектам.
Это RPC-протокол на основе XML.

Плюсы SOAP:
- Мультиязычность и мультиплатформенность. 
- Большой выбор транспортных протоколов.
- Возращает коды ошибок.
- Есть расширения для безопасности. 

Минусы SOAP:
- Только XML.
- Требуют много трафика.
- Сложность создания серверов SOAP API.

## gRPC 
- Бинарный. 
- Экономит трафик. 
- Язык и схема: Protobuf. 
- Не поддерживает HTTP1.1.
- Хорошо подходит для микросервисов.
