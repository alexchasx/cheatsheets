## HTTP (HyperText Transfer Protocol) 
Это «протокол передачи гипертекста».
Данный протокол версии ниже 2-й является текстовым.
Гипертекстовый документ - документ, который может содержать кликабельные ссылки на другие документы.
Работает по технологии «клиент-сервер», по схеме "запрос-ответ".
Клиент  - запрашивает соединение и посылает запрос.
Сервер  - ожидает соединение и возращает ответ.
Не сохраняет своего состояния.
Для идентификации ресурсов используется глобальные URI.

### Версии HTTP:
- HTTP/1.0: открытие соединения требует нескольких обменов сообщениями, и потому медленно (более эффективно при отправке нескольких сообщений - тёплые соединения).
- HTTP/1.1: соединение можно частично контролировать через заголовок Connection. Использует мультиплексирование сообщений, помогающее держать соединение тёплым. Создание параллельных HTTP-соединений и др.
- HTTPS: данные шифруются протоколами TLS или SSL (устарел). Перед соединением, браузер запрашивает SSL/TLS-сертификат (цифровая подпись сайта) и проверяет  подлинность сертификата в центре сертификации. В отличие от HTTP с TCP-портом 80, для HTTPS по умолчанию используется TCP-порт 443.
- HTTP/2: является бинарным. Может послать содержимое, которое ещё не было запрошено клиентом (на опережение).

### URI
Uniform Resource Identifier - унифицированный (единообразный) идентификатор ресурса. Является либо URL, либо URN, либо одновременно обоими.

- URL (Uniform Resource Locator) — помимо идентификации ресурса, предоставляет ещё и информацию о местонахождении этого ресурса. А 
- URN (Uniform Resource Name) — только идентифицирует ресурс в определённом пространстве имён.

HTTP-сообщение состоит из трёх частей:
1. Стартовая строка — тип сообщения.
2. Заголовки        — параметры передачи.
3. Тело сообщения   — данные сообщения (необязательны). Отделяется от заголовков пустой строкой. 

### Стартовая строка (строка запроса):
- <Метод> URI                 — для версии протокола 0.9
- <Метод> URI HTTP/<Версия>   — для остальных версий

Стартовая строка запроса:   GET /wiki/HTTP HTTP/1.0
Стартовая строка ответа:    HTTP/1.0 200 OK

### Методы

• OPTIONS - для определения возможностей веб-сервера или параметров соединения.

• GET - запрос на получение данных. Дополнительные данные могут быть переданы через строку запроса. Можно также начать какой-либо процесс. 

• HEAD - запрос без тела. Позволяет узнать размер запрашиваемого ресурса и другие мета-данные.

• POST - запрос на передачу данных на ресурс без изменения уже существующих (неидемпотентный), то есть повторение запросов может создавать дубликаты. Поддерживает отправку различных типов файлов

• PUT - запрос на замену данных на ресурсе. Является идемпотентным (в отличие от POST).

• PATCH - запрос на частичное изменение данных на ресурсе. Может быть неидемпотентным (пример: добавление лайков).

• DELETE - запрос на удаление данных ресурса.

• TRACE - показывает какую информацию промежуточные серверы изменяют в запросе.

• CONNECT - запрашивает двустороннюю связь с ресурсом. Можно использовать для открытия туннеля.

## Коды состояния (не все):
### 1xx - Информационные: 
Через протокол HTTP1.0 сообщения с такими кодами должны игнорироваться.

- 100 Continue            - продолжай пересылать заголовки
- 101 Switching Protocols - сервер переключает протокол
- 102 Processing          - идёт обработка запроса
- 103 Early Hints         - "Раняя подсказка" (начать предварительную загрузку пока сервер готовит ответ)

### 2хх - Success (Успех)
- 200 OK              — успешный запрос
- 201 Created         — создан новый ресурс
- 202 Accepted        — запрос принят и идёт его обработка
- 203 Non-Authoritative Information - информация взята не из первичного источника
- 204 No Content      - ответ без тела сообщения
- 205 Reset Content   - сбросьте введённые данные
- 206 Partial Content - возвратил только часть контента
- 207 Multi-Status    - выполнены нескольких операций
- ...

### 3хх - Redirection (Перенаправление)
- 300 Multiple Choices - есть список альтернатив перенаправления
- 301 Moved Permanently - окончательно перенесен на новый URI, указанный в Location
- 302 Found — временно доступен по другому URI, указанному в Location
- 303 See Other — перенаправление не на новый ресурс, а на другую страницу
- 304 Not Modified - перенаправление на кешированный ресурс
- 305 Use Proxy
- 307 Temporary Redirect - временно перемещён в URL-адрес, указанный в Location
- 308 Permanent Redirect - окончательно перенесен на новый URI, указанный в Location

### 4xx - Client Error (Ошибка клиента)
- 400 Bad Request - неправильный синтаксис запроса
- 401 Unauthorized - не авторизован
- 402 Payment Required - требуется оплата
- 403 Forbidden - доступ запрещён
- 404 Not Found - не найден
- 405 Method Not Allowed - метод запроса запрещён
- 406 Not Acceptable - ответ не соответствует списку допустимых значений
- 407 Proxy Authentication Required - требует аутентификации на прокси-сервере
- 408 Request Timeout - не дождался ответа со стороны клиента
- ... 

### 5хх - Server Error (Ошибка сервера)
- 500 Internal Server Error - неожиданная ошибка на сервере
- 501 Not Implemeted - метод запроса не поддерживается сервером
- 502 Bad Gateway - сервер, как прокси, получил неверный ответ от другого сервера
- 503 Service Unavaibale - сервер не готов обработать данный запрос
- 504 Gateway Timeout - сервер, как прокси, не получил ответ вовремя от другого сервера
- 505 HTTP Version Not Supported - версия HTTP не поддерживается сервером
- ...
- 526 Invalid SSL Certificate

### Заголовки

Это строки вида "параметр:значение".

несколько заголовков отделяются друг от друга переводом строки
2 перевода строки (то есть пустая строка) - конец заголовков

Примеры:
- Content-Type: text/plain - тип контента (text/plain - выводить текст как есть).
- Content-Type: charset=cp-1251
- Content-Length: 104 - длина контента 104 байта 
- User-Agent: ... - Имя и версия браузера, название и версия операционной системы и др.
- Set-Cookie: cart=63:2; Secure - сохранить куки (Secure - только для HTTPS)

Разделяются на четыре основных группы:
• General Headers («Основные заголовки») — могут включаться в любое сообщение клиента и сервера;
• Request Headers («Заголовки запроса») — используются только в запросах клиента;
• Response Headers («Заголовки ответа») — только для ответов от сервера;
• Entity Headers («Заголовки сущности») — сопровождают каждую сущность сообщения.

Можно вводить свои заголовки. К именам таких заголовков добавляют префикс «X-», но не всегда

### Тело сообщения (message-body)

Если оно присутствует, используется для передачи тела объекта.
Тело сообщения отличается от тела объекта (entity-body), 
когда применяется кодирование передачи (заголовок Transfer-Encoding)
Если тело сообщения присутствует, то добавл. заголовок Content-Length или Transfer-Encoding.
Content-Length позволяет определить конец тела ответа.
Никакие ответы с кодами состояния 1xx, 204 (Нет содержимого, No Content), 
и 304 (Не модифицирован, Not Modified) не должны содержать тела сообщения. 
Все другие ответы содержат тело сообщения, даже если оно имеет нулевую длину.

----------------- HTTPS (HyperText Transfer Protocol Secure) 
— расширение протокола HTTP для поддержки шифрования 
в целях повышения безопасности.
Это обычный HTTP, работающий через шифрованные транспортные механизмы SSL и TLS

TLS (transport layer security — Протокол защиты транспортного уровня), 
как и его предшественник SSL (secure sockets layer — слой защищённых сокетов), 
— криптографические протоколы, обеспечивающие защищённую передачу данных 

Схема работы HTTPS:
• Браузер пользователя просит предоставить SSL-сертификат.
• Сайт на HTTPS отправляет сертификат.
• Браузер проверяет подлинность сертификата в центре сертификации.
• Браузер и сайт договариваются о симметричном ключе при помощи асимметричного шифрования.
• Браузер и сайт передают зашифрованную информацию.

Поисковые системы с недоверием относятся к сайтам, работающим по HTTP-протоколу (нужен HTTPS)
